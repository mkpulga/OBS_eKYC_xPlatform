# Endpoint mapping matrix

All paths below use the selected collection's `/api/v1` prefix. All requests carry the configured `X-Obs-Token`. Login requests are `noauth`; other requests inherit staff Bearer authentication. PII is a separate credential. `applicationId` accepts a citizen ID/reference/CID according to the collection description; `citizenId` route resolution is not established by current pending-record code.

**Implemented means core code exists. Screen wiring and Live-verified are separate dimensions.** P04–P10 are now wired in both parallel Privacy Verification screens; P11–P13 remain pending. PrivacyWorkspace preserves existing login/root and accepts citizen ID directly. Requiredness/nullable details not explicitly documented remain unknown; field presence in an example is not a complete schema.

## Response evidence and missing requirements

There are **zero saved response examples**. Scripts assert HTTP 200 for P01, P02, P04, P05, P06, P11, P13. P04/P05 assert business code 0. P02 reads `data[0].token.accesstoken`/`accessToken`; the current case-insensitive parser supports that casing without adding unrelated aliases. P05's description/script names `data[0].verified`, `expiresAt`, `authorizedSections`, and cookie `pii_access_token`. The expiry format and section values are unspecified.

P11's script reads `data[0].piiVerificationRequired` and `piiAuthorizedSections`; it does not assert a full detail schema. P06 logs the JSON without defining its shape. P13 only asserts HTTP 200 and defines no metric fields. These observations cannot prove successful real-server payloads. Other response status codes, content types, error schemas, nullable fields and backend permission enforcement remain Not tested.

Follow-up evidence: the user supplied dashboard, status, four sections and both detail bodies; exact PII/login cookie names were confirmed. Typed mappings and synthetic tests are in [DASHBOARD-EVIDENCE.md](DASHBOARD-EVIDENCE.md) and [PRIVACY-EVIDENCE.md](PRIVACY-EVIDENCE.md). Status and login HTTP 200/business 0 were reported; dashboard/section/detail HTTP statuses were not supplied. The assistant executed no authenticated requests. Actual renewal/rotation and full screen acceptance remain unverified.

The complete sanitized per-request headers, disabled flags, query names, body type structure, variable references, script events/assertions, paths and classifications are in [endpoint-inventory.json](endpoint-inventory.json).
